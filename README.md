# signal-or-noise

> **怎么判断一个数据结论是真的，还是运气？**

**关键词**：过拟合 · 假阳性 · 多重比较 · 样本外验证 · p-hacking · 回测过拟合 · 自欺

---

## 这是什么

**一份防自欺的检查清单。**

**它解决的问题是：**

> **你以为你在"发现规律"，其实你在"从噪声里挑一个好看的"。**

**这份东西是从一套交易策略验证实践中抽象出来的（一年、15 个方向、全部为负）。**
**但它管的不是交易，是**结论**——任何"我从数据里发现了一个规律"的场合都用得上。**

---

## 30 秒版

**四条核心规则：**

| # | 规则 |
|---|---|
| **1** | **先声明，后测量** —— 跑之前写下来"什么叫成功"，跑完不许改 |
| **2** | **数你试了多少次** —— 期望假阳性 = 方案数 × 5%；通过数 ≤ 它 ⇒ 是噪声 |
| **3** | **留一块没看过的数据** —— 只看一次，用完就废 |
| **4** | **成本先算进去** —— 摩擦成本 ÷ 你要捕捉的幅度，太大就别做 |

**两句话：**

> **搜索集上好看 → 不算数**
> **样本外还在 → 才算数**

**一个反例（真实数据）：**

| | |
|---|---|
| 最好的一次回测 | 毛利 **+194 U** |
| 实际手续费 | **−578 U** |
| **净利** | **−383 U** |
| 要让净利打平，费率须降到 | **1.7 bp**（现实最便宜是 2 bp） |
| 要证实这点正收益存在，需要 | **1362 笔**，而它一年只产生 **69 笔** ⇒ **19.7 年** |

## 一、先声明，后测量

### 规则

**在跑之前，先把两件事写下来：**

1. **什么叫"成功"**（判据 + 阈值）
2. **你要试多少个方案**（网格）

**然后才可以开始跑。跑完之后不许改。**

### 为什么

**因为人是会骗自己的——不是故意的。**

**如果先看结果再定标准，你会不自觉地把标准定在"刚好能过"的位置。**

### 判据要写成能被机械检验的形式

**不能是"感觉好一些"。一份实际用过的判据：**

| # | 判据 | 阈值 |
|---|---|---|
| ① | 效果 | > 0 |
| ② | **t 值** | **≥ 3.0** |
| ③ | 样本量 | **≥ 453** |
| ④ | **分段同号** | 把数据切成三段，三段必须同为正或同为负 |
| ⑤ | **报告总网格数 N** | **期望假阳性 = N × 5%** |

> ⚠️ **②③ 那几个数字是某一个场景的参数，不是普适常数。你要按自己的场景定。**
> **但这五条的**形状**是通用的：效果方向 + 统计显著 + 样本够 + 分段时间稳定 + 报告你找了多少次。**

**★ 第 ④ 条特别值得学：**

**只测"整体为正"是不够的。**
**要看它是不是某一段时间特别好、其他时间很差。**

**如果前后两段排名几乎相反 —— 那是运气，不是规律。**

**真实实例**：某个策略在"前 5.5 年最好的参数"，在后 5.5 年是 **−0.45%**；而"前 5.5 年最差的参数"，后 5.5 年是 **+17.82%**。

## 二、★ 你找了多少次？—— 这是最核心的一节

### 规则

> ## **期望假阳性 = 你试过的方案数 × 5%**
> ## **如果你"通过"的数量 ≤ 这个数 → 是噪声，不是发现。**

### 怎么用

| 你试了 | 期望假阳性 | 意味着 |
|---|---|---|
| 1 个方案 | 0.05 | 通过了基本可信 |
| **20 个方案** | **1** | **通过 1 个 = 什么也没发现** |
| **100 个方案** | **5** | **通过 5 个以内 = 全都可能是噪声** |
| **1125 个方案** | **56** | **通过 56 个以内 = 什么也没发现** |

### ★ 为什么这条最容易被忽略

**因为几乎没人在试完之后，数一数自己试了多少次。**

**而现实里，所有人都这么干：**

| 场景 | 你试了多少次 |
|---|---|
| 调提示词 | 调了 30 版，挑最好的那版 |
| 做内容 | 试了 50 个选题，1 个爆了，然后总结"爆款公式" |
| A/B 测试 | 试了 15 个方案，挑最显著的那个上线 |
| 做交易 | 测了十几个策略，挑回测最好的那个上实盘 |
| 做模型 | 跑了 1125 组参数，报"训练段最优" |

**这些全都踩了同一个坑。**

### 一个抛硬币的类比

> 你抛一枚硬币 10 次，得到 7 次正面。你会说"这枚硬币有问题"吗？不会——你知道这是正常的。
>
> 但换一个场景：你试了 10 个方案，其中一个效果明显更好。
> 你会说"这个方案有效"吗？很多人会说"会"。
>
> **两件事的数学结构是一样的。**

## 三、留一块没看过的数据

### 规则

**在开始之前，先切一块数据出来，锁住，不看。只在最后用它检验一次。**

### 一个实用的切法

| 数据 | 用途 |
|---|---|
| **开发集（60%）** | 随便试、随便调 |
| **验证集（20%）** | 挑方案 |
| **★ 测试集（20%）** | **锁住。只用一次。用完之后如果还要改，就作废，重新切。** |

> ⚠️ **测试集用两次就废了。** 这不是矫情——**第二次用它的时候，你已经知道第一次的结果了。**

### 真实实例

**1125 组参数里挑出的"训练段最优"是 46.86%。**
**而这个"最优"参数在测试段是 48.06% —— 仍然低于基线。**

## 四、摩擦成本必须算进去

### 规则

**任何"收益"都要先减掉摩擦成本，再谈。**

### ★ 更好的一条：看"成本 ÷ 你要捕捉的幅度"

**真实实例（九个品种）：**

| 品种 | 摩擦成本 | 日均波动 | **成本 ÷ 波动** | 结论 |
|---|---|---|---|---|
| 某加密品种 | 10.17 bp | 331 bp | **52%** | ❌ 信号的 1/30 |
| 某农产品 | 9.99 bp | — | **10.0%** | ❌ |
| 某能源 | 7.50 bp | — | 7.5% | ❌ |
| 某股指 | 0.30 bp | 142.9 bp | **4.3%** | ⚠️ 有空间 |
| 某货币 | 1.06 bp | 43 bp | 2.5% | ✅ |
| **某贵金属** | 0.55~0.77 bp | 105 bp | **0.52~0.73%** | ✅ **最好** |

**并且实测出一条规律：**

> **成本超过 3.8 bp 的品种，全部为负 —— 不管逻辑对不对。**

### ⚠️ 抽象到别的领域时注意两件事

**① "3.8 bp"是那条产品线的参数，不能直接搬。**

**② 但"这个比值"这个思路可以搬：**

| 场景 | 摩擦成本 | 你要捕捉的幅度 |
|---|---|---|
| **做内容** | 做一条视频的时间 | 一条视频的预期收益 |
| **A/B 测试** | 改一次产品的工程成本 | 预期的转化提升 |
| **调提示词** | 每次验证的成本 | 预期的效果提升 |

**★ 用法：**

> **比值太大（比如超过 5%）→ 别做。**
> **不是"做不好"，是"分母太小，信号根本盖不住噪声"。**

## 五、★ 三个对照，缺一不可

**很多人只做"看信号会怎样"，不做对照。这是不够的。**

| 对照 | 怎么做 | 它能告诉你什么 |
|---|---|---|
| **① 反向对照** | **把信号反着做** | 若反着做也为正 ⇒ **信号不含方向信息，利润来自别处** |
| **② 尾部对照** | **去掉最好的 1/2/3 笔** | 若去掉几笔就翻负 ⇒ **结果是少数极端事件撑起来的，不可重复** |
| **③ 随机对照** | **随机入场，其余规则不变** | 若与基准同量级 ⇒ **利润来自规则之外的漂移，不是信号** |

### 真实实例：6 个格子的尾部对照

| 格子 | 基准净利 | **去掉最好 1 笔** | 去掉最好 3 笔 |
|---|---|---|---|
| A | +704.71 | **−577.28** | −1573.62 |
| B | +430.06 | **−851.93** | −1848.27 |
| C | +2963.71 | +1602.96 | **−316.34** |
| D | +553.29 | **−667.63** | −1256.11 |
| E | +607.47 | **−613.45** | −1201.93 |
| F | +944.61 | **−276.31** | −1226.24 |

> **👉 6 个格子里，5 个"去掉最好的 1 笔"就翻负。剩下那个去掉最好 3 笔翻负。**

### 真实实例：随机对照揭示了更精确的结论

**做了 20 次同长度的随机择时，看胜率分布：**

> **49.81% ~ 50.03%（均值 49.91%）**

**而被测信号实测是 47.4% ~ 49.2% —— 系统性落在随机分布的左侧。**

**所以结论不是"它没用"，而是：**

> ## **它不是"无信息"，而是"弱反向信息"。**

**这比"没用"更精确，也更有用。**

## 六、★ 先排除"实现错"，再谈"方法不行"

### 规则

> ## **在你说"这个方法不行"之前，先证明"你的实现是对的"。**

### 为什么

**因为"方法没用"和"我做错了"长得一模一样——都表现为"结果不好"。**

**而人的第一个反应总是"方法不行"，不是"我可能有 bug"。**

### 真实案例

**一个方法做了五个版本，结果是：**

| 版本 | 结果 |
|---|---|
| v3 | −44.7%（胜率 47.5%） |
| v4 | −24.6%（胜率 27.1%） |
| **v5** | **−15.3%，但胜率只有 16.3%** |

**看起来在稳步改善。但 v5 那个 16.3% 的胜率不对劲——**

**一个实现正确的模型，胜率不该是 16%。这个数字本身说明：测的不是那个方法，是实现错的东西。**

**由此得出的判读标准：**

> **改完胜率回到合理区间但仍然是负的 ⇒ 才能开始说"这个方法不行"。**
> **改完变成正的 ⇒ 说明前几版的失败全是实现问题。**

### 三个具体检查

#### ① 未来函数 / 数据泄漏

**问自己：我做判断的时候，用到了"那个时候还不知道"的信息吗？**

**别的领域的同一个坑：**
- **A/B 测试**：你把测试期的数据用进了分流决策吗？
- **调提示词**：你用测试集的结果去改提示词了吗？
- **内容分析**：**你用"最终火了"的结论，去解释"为什么当时会火"吗？**（最典型）

#### ② 三个对照（见第五节）

#### ③ 实现偏差登记

**把所有"我知道我这里做得不完美"的地方写下来。**

**真实案例（数据本身是错的）：**

| # | 问题 | 后果 |
|---|---|---|
| **1** | **历史数据拼接错位一根 K 线** | 逐行核对 5727 行：与本行一致 **0 行**，与**前一行**一致 **5678 行（99.1%）** |
| **2** | 指标实现不是标准的 | 用了简单平均，而标准要求是 EMA |
| **3** | 回测端和实盘端规则不一致 | 阈值都不同 |
| **4** | **"事件"被当成"状态"，重复计数** | 13,337 次信号实际只有 9,748 段 ⇒ **同一波行情当成几十笔** |

> **第 1 条尤其致命：如果没核对，会拿一份"未来函数反过来"的数据得出一个完全错误的结论——而那个结论看起来会非常正常。**

## 八、在别的领域怎么用

### 例 1 · 内容运营（"我发现了爆款公式"）

- **你试了 50 个选题，1 个爆了 → 期望假阳性 = 50 × 5% = 2.5 → 1 个爆不算证据**
- **尾部对照：去掉最好的那 1 条，规律还成立吗？**
- **随机对照：随便发 50 条，也会有 1 条爆**

> **大多数人总结的"爆款公式"，在数学上等于"我抛了 50 次硬币，有 1 次连续 5 个正面"。**

### 例 2 · A/B 测试（"这个方案提升了 8%"）

- 网格 = 你试了几个方案 → 期望假阳性
- 对照 = **什么都不改**
- **实现检查：埋点对吗？分流均匀吗？测试期有没有特殊事件？**

### 例 3 · ★ 调 AI / 提示词（"这版效果最好"）

**这是现在最多人踩坑、又最少人意识到的地方。**

- **你调了 30 版 → 期望假阳性 = 1.5 → 最好的那版很可能只是运气**
- **样本外：换一批你调的时候没看过的输入**
- **随机对照：原始那版 / 随便一版**

> **"我调了 30 版提示词，第 23 版最好"——这句话在统计上几乎没有信息量。**

### 例 4 · 市场调研（"很多用户说需要这个功能"）

- 你问了 20 个功能点，3 个被提到 → 期望假阳性 = 1
- **对照：问一个明显不需要的功能，也会有人说"挺好"**
- **★ 别问"你会不会买"，问"你上次为类似的东西花过钱吗"**

## 九、边界

### 能搬到别的领域的

| | |
|---|---|
| 假阳性控制（网格数 × 5%） | ✅ 数学，通用 |
| 样本外验证 | ✅ 通用 |
| 预声明判据 | ✅ 通用 |
| 分段同号 | ✅ 通用 |
| **三个对照** | ✅ 通用 |
| 报错也报对 | ✅ 通用 |

### 不能搬的

| | 为什么 |
|---|---|
| 具体的 t 阈值、样本量、成本阈值 | **那是某个场景的参数，换个场景就不对了** |
| **"成本 ÷ 波动"里的"波动"** | **要换成你那个领域的"信号幅度"** |

### ★ 最重要的一条边界

> ## **这套方法能帮你"否掉假的"，但不能帮你"找到真的"。**
> ## **它是个筛子，不是个矿。**

**它能告诉你"这个结论不可信"，但它不会告诉你"下一个该做什么"。**
